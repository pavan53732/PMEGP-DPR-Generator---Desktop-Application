# DPRPACKAGE.xls Complete Knowledge Base

## 1. Executive Summary

### What the workbook is

DPRPACKAGE.xls is a **PMEGP (Prime Minister's Employment Generation Programme) Detailed Project Report (DPR) generator workbook**. It is a Microsoft Excel 97-2003 (.xls) BIFF8 format workbook that serves as the canonical data model, business rules container, financial engine, and output template for PMEGP DPR generation.

### Why it exists

The workbook was created to standardize the DPR preparation process for PMEGP applicants, banks, and implementing agencies (KVIC, KVIB, DIC, COIR Board). It allows a user to input applicant details, project costs, financial data, and narrative text, then automatically generates:

1. **Application Form** — PMEGP standard application
2. **Detailed Project Report (DPR)** — Cost tables, subsidy calculations, narratives
3. **Comprehensive Project Report** — Full financial analysis
4. **Cover Page** — Front page with summary

### How PMEGP uses it

PMEGP is a credit-linked subsidy scheme. The workbook calculates:

- Project cost components (building, machinery, working capital, etc.)
- Own contribution percentage (5% or 10% based on category)
- Bank finance percentage (95% or 90%)
- Margin money / subsidy percentage (15%-35% based on category, location, gender)
- Subsidy cap validation (₹5L to ₹50L depending on education and business type)

### How the application must use it

The application must treat the workbook as:

1. **Canonical schema source** — all field names, types, enumerations, and relationships are defined in the workbook
2. **Business rules container** — all percentage calculations, conditional logic, and subsidy rules originate here
3. **Output template definition** — all print layouts, merged cell structures, and section ordering are defined here
4. **Validation source** — while no Excel validations exist, the formula patterns define implicit validation rules

### Why it is the canonical source of truth

The workbook is the **single authoritative artifact** that encodes all PMEGP DPR rules. No other document captures:

- The exact 15-category enumeration for social categories
- The cascading margin money logic based on gender + category + location
- The subsidy cap logic with PMEGP-specific limits
- The exact layout and section ordering of the DPR output

### Why UI must mirror workbook structure

The workbook's DataSheet row structure maps directly to the application wizard flow. Each row block in DataSheet corresponds to a logical UI step. Deviating from this structure risks:

- Missing required fields
- Incorrect formula dependencies
- Broken output generation
- Mismatched enumeration values

## 3. Workbook Architecture

```
┌─────────────────────────────────────────────────────────────────────┐
│                        INPUT SHEET                                  │
│                        DataSheet                                    │
│  (Rows 5-180: user input + intermediate calculated values)          │
│  (Rows 182-268: narrative text, addresses, signatures)              │
│  (Hidden cols K-T: enumeration indices, percentages, helpers)       │
└────┬───────────────────────┬──────────────────────┬─────────────────┘
     │                       │                      │
     ▼                       ▼                      ▼
┌────────────┐    ┌──────────────────┐   ┌─────────────────────┐
│Application_│    │   DPR_print      │   │  Project_Report     │
│   form     │    │  (Print Output)  │   │  (Detailed Report   │
│ (Form Gen) │    │  Cost + Subsidy  │   │   + Financials)     │
└────────────┘    └────────┬─────────┘   └──────────┬──────────┘
                           │                        │
                           └──────────┬─────────────┘
                                      ▼
                            ┌──────────────────┐
                            │   DPR_FRONT      │
                            │  (Cover Page)    │
                            └──────────────────┘
```

### Data Flow

1. **User inputs data** into DataSheet visible cells (B8, F41:G47, F54:G66, etc.)
2. **Hidden indices** in column M are set by user selections (1=Male, 1=KVIC, 1=Rural, etc.)
3. **Formulas calculate**: cost items (IF patterns), totals (SUM), percentages (conditional IF)
4. **Output sheets reference** DataSheet directly:
   - Application_form: 6 cell references from DataSheet
   - DPR_print: ~200+ direct range references from DataSheet
   - Project_Report: ~100+ direct cell references from DataSheet + narratives
5. **DPR_FRONT references** DPR_print/Project_Report for summary values

### Architecture Rules

- **Strict DAG** — no circular references exist
- **DataSheet is the root** — all user input enters here
- **Output sheets are consumers** — they never write back to DataSheet
- **All references are direct** — no named range lookups, no INDIRECT/OFFSET

## 13. Financial Engine Analysis

### Architecture

The financial engine is **entirely formula-driven** with these characteristics:

- All calculations are embedded as Excel formulas — no VBA, no macros
- Cost items use `IF(F>=1,F*G,G)` pattern (quantity × rate, default to rate if qty=0)
- Totals use SUM aggregation
- Percentages use conditional IF based on hidden M-column indices
- No manual hardcoding — all values are computed

### Key Financial Calculations

| Calculation | Formula | Location |
|------------|---------|----------|
| Building Cost | `H41:H47` = IF(F>=1,F*G,G); H48 = SUM(H41:H47) | DataSheet |
| Machinery Cost | `H54:H66` = IF(F>=1,F*G,G); H67 = SUM(H54:H66) | DataSheet |
| Working Capital | `H76` = SUM(H70:I74) | DataSheet |
| Own Contribution % | `G85` = IF(AND(M55=1,M70=9),10%,5%) | DataSheet |
| Bank Finance % | `G86` = 100%-G85 | DataSheet |
| Margin Money % | `G87` = IF(M64=2,...) | DataSheet |
| Total Sales | `H102` = SUM(H94:H101) | DataSheet |
| Wages | `H121:H127` = E*F*12; H128 = SUM | DataSheet |
| Salaries | `H134:H138` = E*F*12; H139 = SUM | DataSheet |
| Overheads | `H157:H171` = F*H102 (% of sales) | DataSheet |
| Total Project Cost | `H119` = H93+H108+H109+H111+H113+H117 | DPR_print |
| Subsidy Amount | `H131` = Multi-level IF with caps | DPR_print |

### Subsidy Logic

The subsidy calculation in DPR_print!F131 implements:

```
If Education < 8th AND Service AND Cost > ₹5L → Cap at ₹5L message
If Education < 8th AND Manufacturing AND Cost > ₹10L → Cap at ₹10L message
If Education >= 8th AND Service AND Cost > ₹20L → Cap at ₹20L with subsidy%
If Education >= 8th AND Manufacturing AND Cost > ₹50L → Cap at ₹50L with subsidy%
Otherwise → Full cost × subsidy%
```

## 20. Reverse Engineering Conclusions

### What the workbook is really doing

The workbook is a **self-contained DPR generation application** disguised as an Excel spreadsheet. It serves as:

- **Database**: DataSheet stores all input data
- **Business Logic Engine**: Formulas calculate everything from costs to subsidies
- **Template Engine**: Output sheets render formatted reports
- **Rule Repository**: PMEGP rules encoded as IF formulas in hidden helper columns

### Master Input vs Output

| Master Input | Output |
|-------------|--------|
| DataSheet (rows 5-180 visible) | Application_form |
| DataSheet (rows 182-268 hidden narrative) | DPR_print |
| DataSheet (hidden K-T columns) | Project_Report |
| | DPR_FRONT |

### Stable Parts

- DataSheet column structure (A-J visible, K-T hidden)
- Core formula patterns (IF-based cost, SUM totals, conditional percentages)
- Enumeration values (agency, category, education lists)

### Fragile Parts

- Direct cell references between sheets — row insertion breaks everything
- Row 94 in DPR_print (broken)
- M-column indices tied to specific row positions in L-column
- Print area boundaries — if content expands, print layout shifts

### Broken Parts

- DPR_print!B94 `#REF!` error
- `_xlfn.SINGLE` orphaned named range
- DataSheet!M36 `#VALUE!`

### Most Important for the Application

1. **DataSheet column/row structure** defines the entire data model
2. **Hidden enumeration columns L-M** define all selection values
3. **Percentage formulas G85-G87** define the financing logic
4. **Subsidy cap formula** in DPR_print!F131 defines the PMEGP-specific cost limits
5. **Output sheet layouts** define the PDF render structure
