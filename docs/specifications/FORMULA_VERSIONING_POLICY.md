# Formula Versioning Policy

## 1. Overview
The financial calculations for PMEGP applications are driven by strict governmental formulas (e.g., Margin Money %, Subsidy %). This policy defines how the application tracks, updates, and audits these formulas over time.

## 2. The Formula Registry Hash
Every project and export must be cryptographically tied to a specific `formulaRegistryHash`. This hash represents the exact state of all mathematical formulas used during the project's calculation. 
- It is generated by hashing the contents of `FormulaRegistry.md` (or the equivalent runtime calculation engine module).
- This ensures that if a DPR was generated on Jan 1st, 2024, an auditor can mathematically prove exactly which formulas were active on that date.

## 3. Validation Contract
The core system enforces the following Validation Contract during runtime and generation:

`Project.formulaRegistryHash` == `Runtime.ActiveFormulaHash`

1. **If Match**: Calculations proceed normally.
2. **If Mismatch (Older Version)**: The system prompts the user: *"Your project was created with an older version of the PMEGP rules. Would you like to upgrade to the latest rules (this may change your subsidy amount) or continue with the legacy rules?"*
3. **If Mismatch (Unknown Hash)**: The system flags the project as `DIRTY/CUSTOM` and attaches a warning to all exports.

## 4. Upgrading Formulas
When the government updates PMEGP rules (e.g., changing the Urban/Service cap from 10L to 20L):
1. A new `FormulaRegistry.json` version is created.
2. A new `formulaVersion` (e.g., `v2.0`) and corresponding Hash are generated.
3. Old hashes remain in the system to support read-only viewing and legacy PDF generation of past applications.
